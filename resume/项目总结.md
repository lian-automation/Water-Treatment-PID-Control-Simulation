# 项目总结（第一人称复盘，约 600 字）

这个项目是我为求职准备的"过程控制 + 工业软件"作品集：在没有真实仪表和
PLC 的条件下，把「FOPDT 过程模型 → 增量式 PID → Modbus/TCP 联调 → Web
看板」整条链路完整做了一遍。水处理行业加药（泵开度→余氯）和曝气（风机频率
→溶解氧）是两个典型的慢速、大滞后回路，我用一阶惯性加纯滞后模型仿真它们，
采样周期 1 秒，并叠加高斯测量噪声和进水负荷扰动，让控制问题尽量接近真实。

**做了什么**：控制器按工业风格实现了增量式 PID——输出限幅、反算法抗积分
饱和、测量死区、手/自动无扰切换、微分先行加不完全微分，参数可以在线修改；
整定方面用两点法从阶跃响应反推 K/T/τ，再套 Z-N 公式并做工程修正；通信层用
pymodbus 搭了双 Unit 的 Modbus/TCP 从站模拟 PLC，SP/PV/OP/手自动/报警码/
心跳映射到 HR0~HR5；看板用 Flask 加 ECharts，双回路实时趋势、最近 500 点
回看、SP 下发、手自动切换和在线整定都能点得动。

**踩的坑**：最大的坑有三个。一是增量式算法里我把微分"位置值"直接当增量累
加进输出，等效于多串了一个积分器，闭环实测发散成等幅振荡——重新推导后才
意识到微分增量的正确形态是相邻两拍位置值之差；二是噪声环境下的微分项，N=5
的常规滤波系数在强整定下会放大测量噪声，曝气回路出现周期约 350 秒的等幅振
荡，把滤波加强到 Td/2 才解决，这也让我真正理解了"不完全微分"存在的意义；
三是看板作为 Modbus 主站时，轮询线程和下发线程共用一条 TCP 连接没加锁，
事务 ID 错乱导致一半请求失败，加锁串行化后恢复稳定。

**结果数字（均为仿真验证值）**：两点法辨识误差 K 为 0%、T 小于 0.1%、τ 约
1 秒；与经验保守参数对比，工程修正参数让负荷扰动场景的最大偏差从 1.28%FS
降到 0.63%FS（加药）、0.82% 到 0.16%FS（曝气），恢复时间从 319 秒缩短到
173 秒；Modbus 主站自测 13 项全部通过。整个项目也让我把课堂上的 PID 公式
落成了能跑、能测、能演示的完整系统。
