## 5C. 判据修订记录（2026-09）

**问题**：修订前对真实从站实测 3 次完整自测 = 16/17、16/17、15/17（冷启动与预热
均失败），坐实上轮"17/17 主站自测"不可复现。根因："闭环在调"判据的 8s 观察窗
落在加药回路 τ=30s/T=120s 的过程纯滞后死区内，SP 阶跃 +10% 后 8s 内 PV 仍被
测量噪声（σ=0.02）主导，判据退化为掷硬币；60s 轨迹探针证明回路本身在调
（PV 1.06→1.72 向 SP 收敛）——问题在判据窗口，不在控制回路。

**修复**（`plc_link/modbus_client_test.py`，17 项结构不变）：
1. 判据改验**控制器输出 OP 对 SP 阶跃的即时响应**：增量式 PID 比例增量
   dP=Kp×(e[k]-e[k-1]) 与 SP 阶跃同拍生效，不经过过程滞后；
2. 阶跃改为 **SP 下调 30%**：冷启动时控制器深饱和（曝气 OP 顶格 50Hz）/大误差
   爬坡（加药 OP≈32%），积分项以 Kp/Ti×e 回拉 OP，±10% 小阶跃的响应会被吞掉
   （离线仿真实测 Δ 仅 -0.6~-1.6）；下调 30% 后理论响应 ≥Kp×30%×SP≈9.3%/24Hz；
3. 阈值 **Δ≤-2.5**（方向性）：基准/响应窗口各 3 次采样（间隔 1s）取均值差，
   阈值为执行器量化步长（0.01，寄存器 1 LSB）的 250 倍；离线压测（冷/暖×双回路
   ×400 次，调度抖动 ±0.5 拍+随机噪声种子）最坏组最小响应 -3.9，0 次误判；
4. 时序约定固化：SP 阶跃必须在自动模式下下发且其后无手动保持——实测发现
   "阶跃后紧跟切手动"会让比例增量被手动无扰保持吞掉（e1 照常前移，切回自动后
   dP≈纯噪声，Δ 只剩积分回拉 +2.09，假 FAIL），故模式切换先于 SP 阶跃。
