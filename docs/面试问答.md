# 面试官最可能深挖的 10 个问题及回答要点

> 建议配合 `docs/系统设计说明书.md` 与 `docs/测试报告.md` 的数据回答。
> 所有数字为仿真验证值——面试时要主动强调这一点，体现工程严谨性。

---

## Q1：为什么选增量式 PID，而不是位置式？

**要点**：
1. 增量式输出的是 Δu，天然基于"被限幅后的实际输出"累加，积分饱和倾向小；
2. 手/自动切换时输出从当前值继续增量运算，无扰切换实现简单；
3. 单拍只走一个增量，执行器不会一步打满（对变频泵/风机友好）；
4. 只需最近三个误差样本，无误差累加和，数值上更干净。
**加分**：能说出增量式的代价——积分作用由 e[k] 单点决定，采样周期内扰动
抑制略逊；以及"微分增量=相邻两拍微分位置之差"这个实现细节（我在这上面
踩过坑，把位置值当增量累加导致闭环发散振荡）。

## Q2：抗积分饱和不加以什么后果？增量式控制器怎么实现抗饱和？

**要点**：
1. 后果：输出顶限时积分仍在累积（深饱和），需要反向调节时先"消化"累计，
   造成大超调与长振荡——对余氯这类水质指标意味着超标风险；
2. 本项目增量式的抗饱和是**固有钳位（clamping）**：增量始终累加在
   「上拍已限幅输出」上，u[k]=clamp(u[k−1]+Δu[k])，输出不可能越限
   堆积，退出饱和无拖尾；
3. 控制器另维护**积分退饱和诊断量** `_i_sat_diag`：把限幅截断差按 1/Tt
   回灌给它，供看板/调试观察饱和程度——【它不参与控制律】（表述更正：
   早期文档称之为"反算法"，实际 back 项不进控制律；只有位置式控制器的
   `I += dt/Ti·e + dt/Tt·(u_sat − u_unsat)` 才是真正的反算法）；
4. 为什么不干脆改成位置式反算法？增量式在无扰切换/单拍限速/免积分
   累加和上优势明显（见 Q1），钳位行为本身已正确；换位置式需重写
   控制律并重做全部整定对比实验，收益不成比例；
5. Tt 取 max(Td, 10·dt)；自检新增"强制饱和"段（小量程 + 不可达 SP）让
   饱和真实发生：饱和修正列出现非零值，放宽 SP 后一拍退出、无拖尾。

## Q3：纯滞后 τ 大的回路怎么整定？（加药回路 τ/T = 0.25）

**要点**：
1. 可控性由 τ/T 决定：τ/T 越大，允许的增益越低、响应必然偏慢，物理决定，
   整定不能违背；
2. 经验规则：Kp ∝ T/(K·τ)（Z-N 即此形式），τ 大 → Kp 小、Ti ≈ 2τ 加大；
3. 微分要慎用：大滞后回路的微分相位超前有限，噪声代价可能大于收益；
4. 更根本的对策是**减小等效滞后**：取样点前移、用串级/前馈（如按进水流量
   前馈加药）、或 Smith 预估器（需要较准确的模型，工程上谨慎）；
5. 用本项目数据佐证：加药(τ=30s)比曝气(τ=15s)难整，Z-N 原始值在两回路
   表现差异明显。

## Q4：手自动为什么要无扰切换？怎么实现的？

**要点**：
1. 有扰切换的后果：切自动瞬间控制器输出与执行器实际位置不一致 → 阀门/
   变频器猛跳 → PV 波动，工艺上不可接受；
2. 自动→手动：手动初值取当前输出；手动→自动：输出状态直接承接手操值，
   误差历史照常更新，切回自动瞬间增量从手操值继续累加（手动期间刷新的
   只是积分诊断量，供显示核对，不参与控制）；
3. 参数在线修改同理：积分累计以输出量纲保存，改参数只影响后续增量；
4. 本项目实测：t=600s 从 20% 手操切自动，输出仅到 18.4% 并平滑收敛
   （差值来自微分制动，非积分跳变）。

## Q5：测量噪声环境下微分项怎么处理？

**要点**（本项目完整做了三层）：
1. 微分先行：只对 PV 微分，SP 阶跃不经微分通道（消除微分冲击，实测 OP 不
   再一步打到 100%）；
2. 不完全微分：PV 先过一阶低通再微分，等效 Kp·Td·s/(1+Tdf·s)，Tdf=Td/N；
   我做过 N=5 vs N=2 对照（Z-N 工程修正参数，数据见整定对比报告附录）：
   曝气伺服场景 N=5 超调 127.0%、调节时间覆盖整个观察窗，N=2 同参数
   超调 22.4%、19s；噪声×5 场景 N=2 的 IAE(真值) 降约 32%~64%——
   滤波系数不是拍脑袋定的；
3. 微分限幅：单拍微分增量限制在 ±10% 量程，防残余尖峰；
4. 还可补充：死区门控比例/积分；噪声特别大的回路干脆切除微分改 PI。

## Q6：响应曲线法为什么用两点法（28.3%/63.2%），不用切线法？

**要点**：
1. FOPDT 归一化响应 y/y∞=1−exp(−(t−τ)/T)，28.3% 与 63.2% 两特征点的
   时间间隔恰为 0.667T，是归一化曲线上信息量最大的两点；
2. 切线法要在拐点作切线，噪声下拐点和斜率都极难取准；两点法只需两个
   过阈时刻 + 线性插值，抗噪好、易自动化；
3. 本项目辨识精度：K 误差 0%、T 误差<0.1%、τ 差 1s（离散采样+插值误差）；
4. 注意前提：辨识要在开环、无噪（或多次平均）、单一工作点附近做。

## Q7：Z-N 公式算出来直接用吗？你的工程修正依据是什么？

**要点**：
1. Z-N 目标是 4:1 衰减，本质是把系统推到稳定边界附近，鲁棒性差；
   模型失配+噪声下很容易失稳；
2. 本项目闭环数据：原始 Z-N 在加药回路超调 89%（勉强可用），在曝气回路
   **临界稳定**——超调 121.8%、调节时间 1095 s、持续等幅振荡（相位裕度
   估算≈0°）；
3. 修正规则 Kp×0.5、Ti×1.5 后：负荷最大偏差降低 51%~80%，恢复时间缩短
   46%~100%，伺服 IAE 也最优或接近最优；
4. 结论表述："公式给方向，闭环试验定参数"——这也是真实工厂 PID 回路
   投运的标准流程（先计算预置→阶跃观察→微调）。

## Q8：Modbus 寄存器怎么表示浮点工艺量？地址映射有什么坑？

**要点**：
1. Modbus 寄存器是 16 位整型：本方案用 ×100 定标（0.01 mg/L 分辨率足够，
   500/1000 满量程远小于 65535）；更高分辨率用双寄存器拼 32 位定点或
   IEEE754（注意字序/字节序两种约定）；
2. 地址约定坑：pymodbus 的 zero_mode 决定 HR0 对应客户端地址 0 还是 1，
   必须主从两端实测对齐（我做读写回环验证过）；
3. 心跳寄存器用于判别"通信正常但程序卡死"；报警用位域+消抖计数；
4. DI/DO 真实工程应使用线圈/离散输入功能码，我在组态点表中规划了扩展区
   并注明本版本未启用。

## Q9：看板实时性怎么保证？多线程访问同一个 Modbus 连接要注意什么？

**要点**：
1. 控制周期 1s，看板 1Hz 轮询 /api/data 全量快照即可，轮询实现简单可靠；
   亚秒级需求才值得上 WebSocket/SSE；
2. 历史缓冲用固定长度环形队列（deque maxlen=500），内存有界；
3. **实测踩过的坑**：pymodbus 客户端非线程安全——Flask 请求线程下发 SP 与
   后台轮询线程并发共用一条 TCP 连接时事务 ID 错乱，约一半请求失败；
   解决：所有客户端操作互斥锁串行化 + 读重试。这是主站开发的经典陷阱；
4. 从站侧"单写多读"数据区依赖 GIL 够用于仿真，真实工程要用带锁数据块。

## Q10：如果接入真实仪表和 PLC，这套东西要改什么？怎么平滑过渡？

**要点**：
1. 分层架构的好处：控制层以上不动，把 process.plant 替换成"Modbus 主站
   读取真实 AI/AO"的数据源即可——接口已经抽象（step()/pv 属性）；
2. 必须增加的工程环节：信号量程/断线诊断（4~20mA 断阻检测）、联锁保护
   （低液位停泵、DO 联锁风机的硬接线优先）、限值二重校验（PLC 内 +
   上位机）；
3. 整定流程照搬：现场开环阶跃→两点法辨识→预置参数→闭环微调；
4. 仿真验证的价值：控制算法、寄存器表、看板、异常处理逻辑全部预先验证，
   现场只调"模型差异"部分，风险和工作量大幅下降；
5. 主动说明局限：线性模型不含慢时变与耦合，真实投运要做增益调度或
   自适应，并保留人工手动的最终权限。

## 附：可能的追问速答

| 追问 | 一句话要点 |
|---|---|
| 调节时间怎么定义的？ | 事件后误差最后一次越出 ±2%FS 的相对时刻；扰动场景另配 ±0.5%FS 恢复时间 |
| 为什么负荷场景要关噪声？ | 隔离确定性扰动动力学；高增益会把测量噪声经执行器转成真实波动，混在一起无法归因 |
| IAE 为什么分测量/真值两种？ | 测量 IAE 反映控制器视角负担；真值 IAE 反映真实工艺品质，强噪声下两者差异本身就是结论 |
| 死区会不会引起极限环？ | 死区小于噪声水平时基本不激活；设置原则是低于工艺允许波动带宽 |
| 下一步改进？ | 增益调度适应负荷变化、进水流量前馈、Smith 预估对比实验、WebSocket 多客户端广播 |
